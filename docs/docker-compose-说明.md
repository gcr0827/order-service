# docker-compose 说明（本地开发环境）

> 配套 `docker-compose.yml`。**这份文档的用途**：① 自己复习 ② W4 写项目说明时直接复用
> **方法**：对配置文件的每一行都问自己「**删掉这行会怎样？**」——答得出后果 = 懂了；答不出 = 抄的。

---

## ★1 为什么锁 `mysql:8.0` 而不是 `latest`？

**不是为了"稳定"，是为了「可复现」。**

- `latest` 是一个**会漂移的标签**：今天拉到 8.0，下个月可能拉到 8.4 或 9.x
- 后果：**我本机能跑、同事/CI 不能跑**；线上和本地不一致；甚至同一个 commit 在不同时间构建出不同环境
- 更具体的风险：MySQL 大版本升级会改默认值（如认证插件 `caching_sha2_password`、
  默认字符集、`sql_mode`），这些会**静默改变行为**

> ✅ 正确说法：「锁版本是为了**可复现**——同一个 tag 永远拉到同一个镜像，
> 而 `latest` 会漂移，导致本地/CI/线上不一致。」
> ❌ 「latest 不稳定」——不准确，它只是**不可预测**。

## ★2 `"3306:3306"` 左右各是什么？Go 该连哪个地址？

**格式：`宿主机端口:容器端口`。**

```
       宿主机（WSL Ubuntu）
       ┌──────────────────────────────┐
       │  Go 程序（go run）             │
       │      ↓ 连 127.0.0.1:3306      │  ← 连这里！
       │  [宿主机 3306] ──映射──▶       │
       └──────────────────────────────┘
                    │ docker 网络
       ┌────────────▼─────────────────┐
       │  容器 order-mysql             │
       │  mysql 监听容器内的 3306       │
       └──────────────────────────────┘
```

**答**：

| 场景 | 连什么 | 为什么 |
| :--- | :--- | :--- |
| **Go 跑在宿主机**（现在这样，`go run ./cmd/server`） | **`127.0.0.1:3306`** | 因为左边把**宿主机的 3306** 映射到了容器；容器内部 IP 宿主机**访问不到** |
| Go 也放进 compose（**W4 容器化后**） | **`mysql:3306`** | 同一个 network 内，Docker 内置 DNS 用**服务名**解析 |

> ❌ 常见错答：「Go 连容器」——**容器有独立网络命名空间和 IP**，
> 宿主机只能通过**映射出来的端口**访问它。

## ★3 为什么密码走 `.env` 而不是写死？

**因为 `docker-compose.yml` 是要提交到 GitHub 的（面试官会看），而 `.env` 在 `.gitignore` 里。**

三个理由，按重要性：

1. **凭据一旦提交就永久留在 git 历史里** —— 删掉那一行也没用，别人可以翻历史拿到
2. **同一份 compose 文件在不同环境用不同值**（本地 / CI / 测试），写死就失去灵活性
3. **`.env.example` 可以提交**（只有变量名和占位值）→ 别人 `cp .env.example .env` 就能跑

> **加一句能加分**：`.env` 只是**本地开发的简化做法**；真正生产环境应该走
> **secrets manager / 平台注入的环境变量**（K8s Secret、AWS Secrets Manager），
> 而不是把密码放在文件里。**说得出这个边界，比只会用 .env 强。**

## ★4 为什么是 `utf8mb4` 而不是 `utf8`？

**⚠️ 这题有个流传很广的错误答案：「utf8 不支持中文」—— 不对。**

事实：

| | `utf8`（= `utf8mb3`） | `utf8mb4` |
| :--- | :--- | :--- |
| 最大字节数 | **3 字节** | **4 字节** |
| 常用中文（BMP 内，U+4E00–U+9FFF） | ✅ **能存** | ✅ 能存 |
| **emoji**（😀🚀） | ❌ **存不了**（报错或截断） | ✅ 能存 |
| **4 字节生僻字**（𠮷、𡈼 等扩展 B 区及以后） | ❌ 存不了 | ✅ 能存 |
| MySQL 状态 | 8.0 起已 deprecated | 推荐 |

**✅ 正确说法**：

> 「MySQL 的 `utf8` 是**残缺的 UTF-8，最多 3 字节**，存不了 **emoji 和 4 字节生僻字**；
> `utf8mb4` 才是完整的 UTF-8。所以 8.0 起默认就用 utf8mb4，`utf8` 已被标记为 deprecated。」

**为什么这题高频**：它同时考①你知道 MySQL 的 utf8 是个历史坑 ②你理解 UTF-8 的变长编码。

## ★5 为什么数据要落在命名卷上？不挂卷会怎样？

**容器是"用完就扔"的 —— 不挂卷，`docker compose down` 会把整个数据库一起删掉。**

```
不挂卷：
  数据写在容器内部的文件系统里
  → docker compose down 删掉容器
  → 数据随之消失（表、索引、所有数据全没）

挂命名卷（- mysql-data:/var/lib/mysql）：
  数据实际存在 Docker 管理的卷里（独立于容器生命周期）
  → 容器删了，卷还在 → 下次 up，数据原样回来
```

| 命令 | 容器 | **命名卷（数据）** |
| :--- | :--- | :--- |
| `docker compose down` | 删除 | **保留** ✅ |
| `docker compose down -v` | 删除 | **删除** ⚠️ 清库 |

**命名卷 vs bind mount（面试可能追问）**：

| | 命名卷（现在用的） | bind mount（`./data:/var/lib/mysql`） |
| :--- | :--- | :--- |
| 谁管理 | Docker | 你自己 |
| 跨平台 | ✅ 无权限/路径坑 | ⚠️ Windows/WSL 上常有权限问题 |
| 能直接看文件 | ❌（要去 `/var/lib/docker/volumes`） | ✅ |

> 开发环境想直接看数据文件 → bind mount；**想少踩坑 → 命名卷**。

## ★6 healthcheck 解决什么问题？（和 W4 的 `depends_on` 的关系）

**核心：容器「启动了」≠ 服务「就绪了」。**

MySQL 容器启动后还要**初始化数据目录、建库**，可能要几秒到几十秒。
这段时间**容器是 running 的，但 3306 还没在监听** —— 此时去连，必然失败。

**healthcheck 做的事**：让 Docker 周期性执行探测命令，把容器状态从
`starting` → **`healthy`**（`docker compose ps` 里能看到 STATUS 列）。

### 和 `depends_on` 的关系（**这是重点**）

```yaml
# W4 把 Go 服务也放进 compose 时：
services:
  app:
    depends_on:
      mysql:
        condition: service_healthy     # ← 关键：等 mysql 健康，而不是"启动了"
```

| 写法 | 保证什么 |
| :--- | :--- |
| `depends_on: [mysql]` | **只保证启动顺序** —— 先起 mysql 容器，再起 app。**不保证 mysql 就绪** |
| `depends_on: {mysql: {condition: service_healthy}}` | 等 healthcheck 报 healthy 才起 app ✅（**依赖 healthcheck 存在**） |

**没有 healthcheck 会怎样**：app 启动时连不上 MySQL → 连接报错 → 进程退出。
经典现象是「**app 重启两三次之后就好了**」（因为 MySQL 终于起来了）。

### 今天（Go 跑在宿主机）怎么办？

没有 compose 的 `depends_on` 可用，所以解法在 **Go 代码侧**：

- 启动时**重试连接**（比如重试 5 次、每次间隔 1s），或
- 用连接池 + 健康检查，把"首次连接失败"当作可恢复错误

> **这两条都是面试可讲的点**：微服务里"依赖服务未就绪"是常态，
> 所以要有**启动重试 + 健康检查 + 优雅降级**，而不是假设依赖随时可用。

## 命令速查

```bash
docker compose up -d          # 起（后台）
docker compose ps             # 看状态（mysql 应为 healthy）
docker compose logs -f mysql  # 看日志
docker compose down           # 停（数据保留）
docker compose down -v        # 停 + 清数据（⚠️）
docker compose config         # 只校验/渲染配置，不启动（改完文件先跑这个）
```
